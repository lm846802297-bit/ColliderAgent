# SimpleAnalysis tau resolution and MET significance: source contract

This is a targeted source replay, not a stau detector correction. The ATLAS [full Run 2 MET paper](https://arxiv.org/html/2402.05858v2#S9.SS1) refers to [the public SimpleAnalysis framework](https://gitlab.cern.ch/atlas-sa/framework), and [ATL-PHYS-PUB-2022-045](https://cds.cern.ch/record/2839789/files/ATL-PHYS-PUB-2022-045.pdf) describes an implementation in another analysis. The source is pinned at `b11c683f12618c2543ac9de9cc8c5aef2ab02759`. The stau MET itself must be reconstructed with its own hard objects and a disjoint primary-vertex track contribution.

- [METSignificanceCalculator.cxx](https://gitlab.cern.ch/atlas-sa/framework/-/blob/b11c683f12618c2543ac9de9cc8c5aef2ab02759/src/METSignificanceCalculator.cxx) takes MET as an input. The vector used as the residual balance term follows from that MET plus the supplied hard objects. It does **not** reconstruct MET from primary-vertex tracks. Its significance calculation adds a fixed isotropic **10 GeV** soft width, and suppresses the projected covariance correlation when its magnitude reaches 0.9. These are implementation choices for this statistic, not constraints on the physical correlation between tau response and MET response. Do not add the term to calorimeter-tower MET.
- [ObjectResolutions.cxx](https://gitlab.cern.ch/atlas-sa/framework/-/blob/b11c683f12618c2543ac9de9cc8c5aef2ab02759/src/ObjectResolutions.cxx) selects five eta bands of the same **1p0n** tau calibration category, without testing a tau prong/neutral-pion category there, and uses a fixed 0.01-radian azimuthal width. For 49 GeV transverse momentum the five eta maps give fractional radial widths 9.16–13.34%; for 150 GeV, 5.61–9.01%. These are supplied object widths, not stau-ID efficiencies, scale shifts or a multi-prong detector response.
- Edge behaviors matter: the first bin is 15–16 GeV in all tables, but below its center the interpolation branch decrements the value index below the first histogram content. The consumer rejects that interval rather than trusting the value. The original also switches directly to the final bin content on entering its last bin; at 250 GeV and abs(eta)=1.301 the exact native output is 0.0797616094351, while blanket center-to-center linear interpolation would give 0.0798965140388. The separately implemented interface guards the first-bin interval, the upper edge and inputs outside its defined 1p0n/eta domain; it does not change upstream sources.

## Verification

The exact upstream C++ bodies for the rotation, tau lookup and histogram lookup were extracted by function delimiters and compiled unchanged with small scalar object/matrix fixtures; no full framework or detector executable was run. Source and all five table hashes are checked before compiling. An independent Python interpolation matches **70 of 70** safe tests, including eta boundaries, exactly. An independent outer-product sum reproduces the rotated 2x2 covariance and a Schur complement check reproduces significance on a synthetic fixture below the upstream correlation guard. Four unit tests include rejection of an unvalidated prong and low domain. The JSON regenerated byte-identically. No stau ROOT was read, no event was retuned, no signal cutflow or control-region count was changed. This math gate does not produce an independently calibrated MET reconstruction.

## Replay

Get the pinned upstream source into a clean local directory (two .cxx files and five .h files), then copy and run the harness there. The exact upstream source URLs and expected digests are resolved by the script below. Requires Python 3.12 and a C++17 compiler; tested with GCC 14.2.0.
