# Native DDCalc elastic rate and kinematics gate

Parent: independent elastic SHM benchmark at ColliderAgent `6886256018ef89ea6bf1ffacf5a5647c4d712683`. Goal: verify the native standard-elastic detector backend without extending to radiative scattering or calculating an exclusion. Question: can an authentic pinned DDCalc executable reproduce its own published XENON1T demo and agree with an independent halo and Poisson oracle?

Source: `GambitBSM/DDCalc@065c126c563107de090a9644bed997462d72ec61`, upstream v2.3.0 history with unchanged internal version string `2.1.0`. Use the unmodified official Fortran example's first case, XENON1T 2017 and 100 GeV DM with the four signed cross sections specified there. Source pins for the detector model and halo are recorded in the run manifest. Actual environment: temporary, signed Debian gfortran 14.2.0-19; no system installation, external compute, CI or credentials.

Acceptance fixed before native run: the official upstream example produces a positive finite expected signal, observed count 0 and fixed background 0.36 from the pinned detector implementation; a one-case native driver agrees within 1e-10 absolute, and the total fixed-background log likelihood agrees with the full independent Poisson log PMF to 1e-10 absolute. Independently compare native halo inverse speed to all 18 frozen Galactic-shell integral points (absolute tolerance 2e-12 s/km) and native recoil vmin to the frozen 8 keV, 122 GeV nucleus, 50 GeV DM case (absolute tolerance 1e-9 km/s), including exact no support at/above the cutoff. Preserve exact source fingerprints and outputs. The signal rate is a same-backend replay, not an independently validated detector rate or an exclusion. Shared-library/Python wrapper not required.
